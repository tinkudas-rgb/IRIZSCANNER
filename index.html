01 · Bottlenecks & Fixes

Common Scanning Failures & Remedies

Pain Point The Problem The Modern Solution
Hologram Glare Laminated cards produce specular highlights that saturate OCR. Illumination normalization using CLAHE before OCR inference.
Skewed / Rotated Scanning Users hold IDs at arbitrary angles causing perspective distortion. YOLOv8-OBB detects oriented corners & homography warp to bird's-eye.
Blurry Text Out-of-focus captures hide micro-text like Issue Date. Laplacian variance check; scores < 100 are rejected immediately.
Field Confusion OCR sees "CSE" & "Main Campus" but lacks field context. LayoutLMv3 understands positional semantics (text below "Department" ⇒ dept).

Step A

Card Detection & Warping

Model: YOLOv8 (Oriented Bounding Box). Captures 4 card corners from live video, filters by confidence, then performs homography to produce a flat, top-down crop ready for OCR.

  • Input: live camera feed (edge device).
  • Output: perspective-corrected 1024×640 tensor.
  • Extras: auto-suggest re-capture if glare hotspots persist.

Step B

Text Extraction

Model: PaddleOCR (PP-OCRv4). Handles scene text with SVTR recognizer, multi-language lexicons, and lightweight deployment on mobile NPUs.

  • Runs on normalized crop to get sequences & bounding boxes.
  • Feeds LayoutLMv3 with textual tokens + 2D positions.

Step C

Entity Parsing & Validation

Models: LayoutLMv3 + Regex/Fuzzy logic. Maps raw text to Name, Reg No, Dept, Campus, Issue Date, University name.

  • Reg No Regex: ^(\d{4})(\d{6})$.
  • Issue Date Regex: \d{2}[/-]\d{2}[/-]\d{4}.
  • Levenshtein + header anchors for Dept/Campus.

02 · 3-Layer Security

Fake vs Real Decision Stack

Layer 1 · Logical Checks

  • Validate 4-digit year + 6-digit Reg No format.
  • Issue Date year ≥ joining year (Reg No prefix).
  • Dept code embedded in Reg No must match printed Dept text.

Layer 2 · Visual Forgery (ELA)

  • Run Error Level Analysis to catch Photoshop edits.
  • MobileNetV3 classifier trained on CASIA v2 tamper dataset.
  • Highlight suspicious noise around Name/RegNo boxes.

Layer 3 · Font Consistency

  • Siamese network compares Reg No glyphs to gold standard.
  • Detects serif vs sans mismatch, kerning anomalies, stroke width.
  • Triggers manual review when similarity drops below 0.82.

03 · Implementation Notes

Engineering Checklist

  • Edge Compatibility: Models run via ONNX Runtime / TFLite on Android devices with optional GPU delegate.
  • Security: All inference is on-device; only metadata (verdict, hashed Reg No) leaves the device.
  • Observability: Structured logs push to the fraud backend with scores from each layer, making audits painless.
  • Extensibility: Plug in new regexes (e.g., staff IDs) or add risk signals such as duplicate Reg Nos within 90 days.
